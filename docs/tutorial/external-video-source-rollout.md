# 外部视频源：发布步骤与批量导入方案

## 1. 提交并固定发布版本

后端、管理端、用户端分别发布。发布前记录三个仓库的准确提交号，使用 `Java_video` 上已经验证的构建与定向测试，不带入无关工作树改动。外部播放默认开启；显式 `playback-enabled: false` 会覆盖默认值。管理员目录预览仍单独控制，不自动启用任何来源。

## 2. 部署与迁移

- 先确认目标环境、部署版本、备份及回滚窗口。现有库按真实结构确定缺少哪些迁移，不重跑初始化 SQL，不重建已有数据卷。
- 视频源需要 E1-A → M4-A1 → S2 → M5（只执行缺失部分）：`e1a-external-video-source-catalog.sql`、`m4a1-local-video-identity.sql`、`s2-local-episode-source.sql`、`m5-local-episode-import.sql`。不执行未使用的 M4-A2。使用当前初始化 SQL 的新库已含这些结构，不再追加执行 M5。
- M5 允许外部稿件的 `video_url/video_key` 为 NULL。部署前验证分类、封面临时认领和既有 COS 稿件；**不能**把已有外部稿件的库直接退回要求非空播放列的旧版本。异常时先停用外部来源或显式关闭播放开关，旧 COS 投稿与播放照常保留。

## 3. 配置来源并在实际站点验收

- 只配置有权接入且已验收的源，分别填写精确 API/媒体 host:port 允许列表。`bfzyapi.com:443` + `v.fengbao14.com:443` 的单个样本通过隔离探测及 Chromium 实播；不能据此认定同源所有节目可播。未通过的虎牙样本不纳入首批。
- 先按正式站点 Origin 验证小样：管理端预览 → 候选确认并导入 → 审核 → 用户端播放和切线；同时检查未审核稿件、私密访问以及旧 COS 路线。目录可访问不等于 HLS 可播放，探测通过也不保证后续可用。
- 若通过，再逐步扩大已确认线路数；不批量发布、不自动关闭旧投稿。暂停对外播放可设 `playback-enabled: false`，它不撤回浏览器已收到的上游地址。

## `Java_video` 独立发布验收记录

- 仅在 `Java_video` 私有验收环境运行；后端、管理端和用户端监听回环地址，不替换现有服务。独立 MySQL 从基础表应用 E1-A → M4-A1 → S2 → M5，使用新卷，Redis、RabbitMQ 和私有 COS 桶均为本次验收专用。正式环境未改动。
- 首次完整启动发现 `VideoStatusDirtyRecoveryScheduler` 没有给 Spring 指定生产构造器，选择三参构造器后通过 11 项调度相关定向测试，后端重新打包并启动。
- 实际部署的 HTTP API 验证了管理员鉴权、CMS 目录/详情、HLS 探测与确认、真实 COS 封面上传与首次导入、重试复用原 `vid`、待审不可公开播放、审核放行和选集。Chromium 直接访问已部署的两个前端和真实 API，无请求替换，解码播放上游清单及分片。只有一条真实来源进入此验收环境；多线路切换的保持进度行为此前在合成 HLS 试验中通过。没有启用其他源或切换生产流量。
- 发布产物与记录：`/data/home/feibijiubi-source-release.5jMx8c`；`backend-hotfix.log` 与 `release-browser.log` 是上述上线检查的定向记录。

## 后续功能：管理员批量导入，用户按需选线路（待实现）

- 管理端按页多选已授权来源中的作品或分集，先生成待核对清单，再逐项选择现有本地剧集或建草稿。禁止按标题、集数、URL 或时长自动合并。管理员确认是同一集、同一版本和时间轴后，其他来源只追加线路，沿用原 `vid`；不同剪辑不能当成同一条时间轴。
- 首版由管理端限量提交，经现有配额和每集独立事务执行。界面逐项显示待确认、待审核、已复用、失败；已有 `vid` 不重复创建。同一集新增线路不消耗新封面。首次导入仍逐项使用符合所有权要求的 COS 临时封面，不改用 CMS `vod_pic`。失败只处理失败项；结果不明先查询，不自动重发写操作。不做整站采集、后台定时同步或自动审核。
- 用户看的是已发布、可见的视频和通过校验的线路。现有切线已保留进度及播放状态。扩展建议：同一 `vid` 在当前设备记住用户手选线路（只存线路 ID），不可用就提示并提供其他线路；如果要按网络自动选线，另行决定失败回退与探测预算，不预取全部签名地址，也不需要地理定位。
- 验收重点：同一剧集的部分成功重试不另外创建 `vid`、错误映射不覆盖原线路、草稿不被当作已发布，以及不同设备的手选线路不改变本站进度和互动。
