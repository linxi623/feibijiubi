# 人工映射与时长确认实施计划

## 0. 最新简化决定（用户已确认，覆盖下文旧后台任务提案）

首版是管理员同步操作，不做后台队列、通用 operation 表、任务租约、fencing、自动接管或自动恢复。此前提出这些机制是过度设计，不再作为人工流程的前置条件。

流程：选择来源和本地剧集 → 请求线程在事务外有界抓取/探测 → 展示候选 → 管理员确认 → 短事务核对版本并保存关联/时长。探测失败或请求中断由管理员重试，不承诺自动续跑。探测结果由服务端保存或以服务端可验证的方式绑定候选，不能直接信任客户端上报“探测成功”；具体最小实现随确认接口设计，不引入持久任务框架。

保留的正确性约束：
- 保存失败事务回滚；已提交但响应丢失时允许重新查询当前结果，不承诺任意请求都可透明重放。
- 导入锁本地剧集，已有vid就返回既有结果，不再创建第二个video；唯一约束作最后防线。
- 确认提交带预期版本；地址/映射变更或并发修改时返回409，管理员刷新后重新确认。
- 仅记录必要的操作者、操作时间、确认值/理由和关联版本，不另建通用审计平台。
- 来源带token的签名地址是上游播放凭据，不要求自建签名系统；不写日志、不返回普通预览接口，过期后人工更新。首版不实现自动归档/清理或自研加密平台；真实部署前仍需正常的数据库访问权限和备份保护。

已完成A1/A2表文件都未执行。S2现已选择更小的独立三表方案（状态版本、单条候选、稳定来源关联），只依赖A1，不接旧A2四表；旧文件保留，不执行迁移。旧的operation/任务恢复规划不再推进。S2代码及离线测试见[来源绑定与确认](external-video-source-binding.md)，下一步是M5导入事务而不是再加基础设施。

## 1. 已确认决策与边界

用户本轮选择“系统尝试读取媒体时长，管理员确认”，并授权制定计划后实施。

- 管理员明确选择作品及本地剧集；缺失上游剧集 ID 时，由系统生成永久本地身份（36字符小写UUIDv4（无`m:`前缀）），管理员负责映射。集数、标题、URL、数组位置均不是身份。
- **用户追加确认：跨来源的同一视频内容共享一个 `vid`。** 本地作品/剧集身份独立于来源；上游作品只作来源目录，不能充当本地作品主键。管理员确认同一集后，多来源候选映射到同一个本地剧集，各自保存播放线路及证据。
- 一个本地剧集最多绑定一个 `vid`。新增来源/线路不得重新创建视频；冲突必须明确拒绝，不能覆盖原绑定。首次导入者为作者，后续加源不改作者；互动、统计、进度共用原 `vid`。不自动按标题/集数合并；已存在多个 vid 的历史数据另议迁移。
- 每条线路保留自己的探测证据，本地剧集使用管理员确认的统一时长。不同剪辑/广告时间轴不能仅因标题相同就认作等价线路；时长一致本身也不证明内容相同。
- 探测只产生候选时长。管理员可确认或核验后修正；最终必须是有限且大于零的秒数，记录人员、时间、来源及修正理由。
- 无可信时长不创建可互动视频。不修改 PublishedVideoGuard / savePlayProgress；不伪造默认时长。
- 导入者为作者，保留现有审核/分类/可见性、互动与统计协议。替代播放验收前不关闭旧上传；头像、背景和封面 COS 功能保留。
- 只替换上述已决定条款，不意味着旧 E0 全文、任务租约、封面所有权等候选设计全部获批。

## 2. 实施顺序及逐阶段验收

| 阶段 | 实施内容 | 验收边界 |
| --- | --- | --- |
| M1 | HLS 有限媒体清单的纯解析器：有界 UTF-8 输入、EXTINF 精确求和、ENDLIST、结构校验、固定拒绝码 | 离线合成样例；没有网络、没有确认/导入 |
| M2 | 独立受限媒体 GET 与探测组合；精确媒体 host:port 白名单、连接期 DNS 校验、严格 TLS、禁跳转、响应大小和请求次数上限 | 复用已有安全基础但不复用 CMS 查询构造；只授权测试端点，本机测试单独执行 |
| M3 | 管理员目录/作品详情/候选播放线路预览；显式选择媒体清单，呈现探测失败和人工处理状态 | 管理员权限、分页/数量边界、脱敏，不自动建视频 |
| M4 | 独立本地作品/剧集、跨来源多对一人工映射、线路级探测记录、本地统一时长确认及基本操作记录 | S1草稿已完成；S2草稿绑定/确认已实现为离线候选。提交迁移不执行；绑定版本/指纹、CAS、并发失败不覆盖；不承诺透明操作幂等，真实MySQL验证另需授权 |
| M5 | 单集导入事务：锁剧集→确认版本和时长→建 video/video_status→唯一绑定 vid→审计 | 错误回滚、不重复建视频；不自动发布；封面所有权方案先审查 |
| M6 | 播放及选集接口、前端联调、线路更新待审、进度核验，最后关闭旧上传入口 | 真正浏览器播放/源授权需单独证据；不能用后端单元测试代替 |

先完成明确的单条人工流程，不在首轮引入批量采集、自动导入、定时任务或作业租约。以后若加入后台任务，必须先解决旧契约中的 fencing 和源级串行权，不能继承未经实现的承诺。

## 3. 时长探测首版范围

### M1：HLS 候选值，不是媒体真实性证明

- 仅接受以 `#EXTM3U` 开头、具有终止 `#EXT-X-ENDLIST`、结构完整的媒体清单。时长来自分片 `#EXTINF` 的十进制精确求和，不用二进制浮点逐项累加。
- master 清单只返回固定“需选择媒体清单/不支持”原因，不自动递归遍历；直播/缺 ENDLIST、空清单、畸形或超限输入不返回可确认数值。
- 不取分片、不取密钥、不解密、不调用远程 ffprobe。清单声称的时长可能错误，ENDLIST 也不证明 URL 永久不变；管理员确认不能省略。
- byte[] 上限 512 KiB，行数/行长/分片数和数值文本长度都有明确工程限额；不是 HLS 协议的通用限制。失败异常固定码，不回显 URL、原始行或解析异常。
- 返回候选秒数、分片数及原始响应 SHA-256；不返回“已确认”“已发布”“可播放”等结论。
- MP4 在首版自动探测中明确未支持，不能拿文件大小或码率估算充数。后续若做 MP4，应设计有界范围请求与容器解析，不能把任意 URL 交给 ffprobe 让它自行联网。

### M2/M4：防止探测与确认串版本

探测记录至少绑定源、作品、本地剧集/待分配候选、线路候选版本、请求地址指纹、清单内容指纹、候选秒数及探测时间。URL 原文仅在受控服务端保存，不进入普通日志。

确认请求针对服务器已保存的探测记录和候选版本，不接受客户端自行声明“探测成功”。地址或映射版本改变后，旧确认不能批准新候选。管理员修正值另记理由，不篡改原探测证据。已导入视频的时长不通过补齐入口静默更新，以免与进度形成双真值。

内容指纹不是签名，也不能阻止上游在同 URL 替换内容；本地确认记录只证明管理员确认过某次候选，不能声称持续验证上游。
