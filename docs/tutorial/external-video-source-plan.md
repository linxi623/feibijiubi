# 外部视频源接入 TODO 与验收计划

## 1. 已确认的范围

- 工作分支：`feature/external-video-source`，起点 `429bdbf`（原 dev）。
- 仅替换播放视频来源，关闭视频投稿和视频上传凭据入口；保留 COS 头像、背景、封面能力。
- 导入视频归属于执行导入的管理员账号。沿用作者详情、投稿列表、获赞等既有计算语义，不伪造用户。
- 一集对应一个本地 `vid`；互动、收藏、播放进度、统计仍以 `vid` 为单位。
- 保留审核、可见性、分类、用户权限、播放/分享幂等与限流，以及现有 Redis/RabbitMQ 统计协议。
- 首版限授权 MP4/HLS 直链，不接解析站、不执行外部脚本、不代理视频流、不下载视频到 COS。
- 不按标题自动合并不同来源作品或跨线路剧集。无法证明稳定身份时拒绝自动关联，进入人工处理。
- 既有 COS 视频数据不删除、不批量转换；新播放路径不回退到 COS。历史记录的展示/不可播放提示在 E0 中明确，未经授权不批量下架。

## 4. E0 必须固定的设计细节

1. 保留 `video` 与 `video_status`。新增独立播放来源标识，不改变既有“自制/转载”的 `source_type` 语义。COS 视频 key 对外部视频允许为空，不使用假 key。
2. 建立上游作品分组与本地剧集 vid 的绑定。上游无稳定剧集 ID 时，定义可验证的持久身份及变更冲突策略，禁止仅按当前数组下标或可变 URL 重新分配 vid。
3. 一个 vid 可关联多条已确认属于同集的线路地址；无法匹配的线路不自动融合。进度仍保存于原 vid，不引入作品级进度。
4. 外部资源的时长可能未知，不伪造为实际零时长。父代理核实 PublishedVideoGuard 与 savePlayProgress 后决定：首版不放宽既有互动/进度校验；未知时长资源只暂存在资源目录，不创建可互动的 video，管理员补齐可信、有限且大于 0 的时长后才导入。禁止信任任意客户端上报来覆盖时长。
5. 视频标题、简介等须满足现有字段约束；超长、缺失、不合法分类显式处理，不通过任意截断破坏身份。
6. 本地人工编辑、审核、下架、可见性与统计不受同步覆盖；新线路/地址变更的审核策略需明确，不绕过审核。
7. 默认不得向用户返回全部原始播放 URL；新增播放信息接口，验证归属与可见性。地址不是秘密，浏览器直连必然可见。
8. 外部封面和 COS 封面区分所有权，不将外部 URL 转 COS key。外部 URL 需安全校验；后端不得任意抓取。
9. 同步任务使用独立、有限并发执行器，不挤占现有视频统计调度器；源站失败时继续服务本地目录。
